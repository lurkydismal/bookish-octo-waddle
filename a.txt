# Data Structures for glTF Runtime Assets

When a glTF file is loaded, its JSON/binary data is parsed into engine-friendly C structs. These structs pack mesh, material, texture, scene, skeleton and animation data into contiguous, GPU-ready layouts. Below is a comprehensive guide to essential runtime structs, with explanations and memory-layout tips.  

## Mesh Geometry

A **Mesh** holds one drawable primitive: a contiguous array of vertices and an index buffer. Each vertex typically contains position, normal, texcoord, etc. (possibly tangent, bitangent, vertex color, etc.) to support rendering. For example, a minimal vertex in C:

```c
typedef struct {
    float position[3];
    float normal[3];
    float texcoord[2];
    // (Optional: float tangent[3]; float color[4]; etc.)
} Vertex;
```

This matches the common OpenGL layout where “a mesh should at least have vertices with position, normal and texture coordinates” ([LearnOpenGL - Mesh](https://learnopengl.com/Model-Loading/Mesh#:~:text=Let%27s%20review%20a%20bit%20of,diffuse%2Fspecular%20maps)). After parsing glTF, you can pack all Vertex attributes into a single array (`Vertex *vertices`) and a parallel array of indices (`uint32_t *indices`). For example:

```c
typedef struct {
    Vertex *vertices;       // Pointer to contiguous vertex attribute array
    uint32_t *indices;      // Pointer to index array
    size_t vertexCount;
    size_t indexCount;
    int materialIndex;      // Index into Material list
} Mesh;
```

In glTF, each `glTF.mesh` can contain multiple *primitives* (sub-meshes). At runtime it’s common to create one `Mesh` struct per glTF primitive ([How I learned Vulkan and wrote a small game engine with it](https://edw.is/learning-vulkan/#:~:text=%2F%2F%20Each%20,renderer.drawMesh%28mc.meshes%5Bi%5D%2C%20tc.worldTransform%2C%20mc.castShadow)). Each `Mesh` is then uploaded to the GPU as one vertex buffer (VBO) and one index buffer (EBO). Packing vertices and indices into contiguous arrays improves cache locality and lets you call `glBufferData` just once per array. 

- *Vertex Buffers*: Store interleaved attributes (as above) in a single array for better memory locality.  
- *Index Buffers*: Store triangle indices in a flat `uint32_t[]`. Use the smallest index type (16-bit or 32-bit) that fits the mesh size.  
- *Sub-meshes*: If a glTF mesh has multiple primitives, treat each as a separate `Mesh` with its own buffers ([How I learned Vulkan and wrote a small game engine with it](https://edw.is/learning-vulkan/#:~:text=%2F%2F%20Each%20,renderer.drawMesh%28mc.meshes%5Bi%5D%2C%20tc.worldTransform%2C%20mc.castShadow)).

Referencing [LearnOpenGL’s Mesh example](7) for a similar approach: it defines a `struct Vertex { vec3 Position, Normal; vec2 TexCoords; };` and stores `std::vector<Vertex>` and `std::vector<GLuint> indices` ([LearnOpenGL - Mesh](https://learnopengl.com/Model-Loading/Mesh#:~:text=struct%20Vertex%20,glm%3A%3Avec3%20Normal%3B%20glm%3A%3Avec2%20TexCoords%3B)). Our C structs work the same way with raw pointers.  

## Materials and Textures

A **Material** struct contains all PBR parameters and texture references needed for shading. glTF 2.0 uses the metallic-roughness PBR model, so a material typically includes factors and texture indices:

```c
typedef struct {
    char name[64];               // Optional material name
    float baseColorFactor[4];    // RGBA multiplier
    int baseColorTexture;        // Index into texture array (or -1 if none)
    float metallicFactor;        // Scalar [0..1]
    float roughnessFactor;       // Scalar [0..1]
    int metallicRoughnessTexture;// Combined M (B) + R (G) texture
    int normalTexture;           // Normal map
    float normalScale;           // Strength of normal map
    int occlusionTexture;        // Ambient occlusion map
    float occlusionStrength;     // AO strength
    int emissiveTexture;         // Emissive color map
    float emissiveFactor[3];     // RGB multiplier for emissive
    int doubleSided;             // Bool: render both sides?
    enum { ALPHA_OPAQUE, ALPHA_MASK, ALPHA_BLEND } alphaMode;
    float alphaCutoff;           // For ALPHA_MASK mode
} Material;
```

Key notes: 
- `baseColorFactor` and `metallicFactor`/`roughnessFactor` default to 1.0 if not specified.  
- glTF packs metallic (blue channel) and roughness (green channel) into one texture (`metallicRoughnessTexture`) ([glTF™ 2.0 Specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#:~:text=The%20textures%20for%20metalness%20and,than%208%20bits%20per%20channel)). We store this as a single `int` index.  
- Other textures (normal, occlusion, emissive) each have their own `int` index.  
- `alphaMode` handles transparency (opaque, mask, blend) from glTF.  
- `doubleSided` comes from glTF’s material property.  

Each texture index refers to a **Texture** resource, described below. The material’s fields (factors and flags) can be kept as floats/ints in CPU memory and also uploaded to the GPU (as uniform or via push constants) at draw time. 

## Texture References and Samplers

Textures in glTF reference image files plus sampling parameters. We keep a **Texture** struct that holds the file URI and sampler settings, plus a GPU handle once loaded:

```c
typedef struct {
    char uri[128];        // File path or URI of the image
    Sampler sampler;      // Texture sampling parameters
    unsigned int texId;   // GPU texture handle (e.g. OpenGL GLuint)
    int width, height;    // Image dimensions
} Texture;
```

And a **Sampler** struct for wrapping/filter modes:

```c
typedef struct {
    int magFilter;  // e.g. GL_LINEAR, GL_NEAREST
    int minFilter;  // e.g. GL_LINEAR_MIPMAP_LINEAR
    int wrapS;      // e.g. GL_REPEAT
    int wrapT;      // e.g. GL_CLAMP_TO_EDGE
} Sampler;
```

glTF samplers define exactly these properties (“texture filtering and wrapping modes” ([glTF™ 2.0 Specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#:~:text=))). After loading the image data from `uri`, upload it to GPU to get `texId`, and apply the sampler settings. You may also store `width`/`height` for reference (or discard after GPU upload).

- The `Sampler` from glTF can be translated directly into OpenGL/Vulkan parameters.  
- Keep textures in an array or list indexed by `Texture` struct, so materials can reference them by integer index.  

## Scene Graph (Nodes)

glTF represents the scene as a hierarchy of **nodes**, forming a scene graph. Each node may have a transform, a mesh, a skin (for bones), camera, lights, etc., and zero or more children ([glTF-Tutorials/gltfTutorial/gltfTutorial_004_ScenesNodes.md at main · KhronosGroup/glTF-Tutorials · GitHub](https://github.com/KhronosGroup/glTF-Tutorials/blob/main/gltfTutorial/gltfTutorial_004_ScenesNodes.md#:~:text=Each%20node%20can%20contain%20an,scene%20as%20a%20scene%20graph)) ([glTF-Tutorials/gltfTutorial/gltfTutorial_004_ScenesNodes.md at main · KhronosGroup/glTF-Tutorials · GitHub](https://github.com/KhronosGroup/glTF-Tutorials/blob/main/gltfTutorial/gltfTutorial_004_ScenesNodes.md#:~:text=Each%20node%20can%20have%20a,applied%20to%20the%20scene%20elements)). At runtime, use a `Node` struct like:

```c
typedef struct {
    char name[64];         // Optional node name
    int parentIndex;       // Index of parent node (-1 if root)
    int *children;         // Array of child node indices
    int childCount;
    float localMatrix[16];// Local transform (col-major 4x4 matrix)
    float worldMatrix[16];// World transform (computed = parent * local)
    int meshIndex;         // -1 if no mesh
    int skinIndex;         // -1 if no skin (skeleton)
} Node;
```

Each node’s `localMatrix` is built from its glTF `translation`/`rotation`/`scale` (TRS) or directly from the glTF `matrix` field. By design, “each node can have a transform… applied to the node itself and all its children” ([glTF-Tutorials/gltfTutorial/gltfTutorial_004_ScenesNodes.md at main · KhronosGroup/glTF-Tutorials · GitHub](https://github.com/KhronosGroup/glTF-Tutorials/blob/main/gltfTutorial/gltfTutorial_004_ScenesNodes.md#:~:text=Each%20node%20can%20have%20a,applied%20to%20the%20scene%20elements)). During load, accumulate world transforms via parent links. Typically you store just the local TRS and compute the 4×4 matrix, or store the matrix directly. 

Memory layout tips: store all nodes in one array so they pack tightly. Use `parentIndex` and a contiguous array of child indices (or dynamic array) to traverse hierarchies. The scene’s list of root nodes (from `glTF.scenes`) are those with `parentIndex == -1`. 

## Skeletons and Skinning

A **Skin** (skeleton) defines a set of joints (nodes) and their inverse bind-pose matrices ([glTF-Tutorials/gltfTutorial/gltfTutorial_020_Skins.md at main · KhronosGroup/glTF-Tutorials · GitHub](https://github.com/KhronosGroup/glTF-Tutorials/blob/main/gltfTutorial/gltfTutorial_020_Skins.md#:~:text=The%20skin%20contains%20an%20array,joint%2C%20in%20its%20initial%20configuration)). In glTF, a `skin` has an array of `joints` (indices into the node array) and an `inverseBindMatrices` accessor. At runtime:

```c
typedef struct {
    int jointCount;
    int *jointNodeIndices;   // Array of node indices for each joint
    float *inverseBindMatrices; // Flat array [jointCount][16] (each mat4)
    int skeletonRoot;        // Optionally the index of the root joint
} Skin;
```

- `jointNodeIndices[i]` refers to the Node index for joint *i*. 
- `inverseBindMatrices` is a flat float array of length `16 * jointCount`, where each 16 floats is the inverse bind matrix for that joint. This matrix transforms vertices into joint-local space. 
- glTF guarantees each matrix is the inverse of the joint’s global transform at bind time ([glTF-Tutorials/gltfTutorial/gltfTutorial_020_Skins.md at main · KhronosGroup/glTF-Tutorials · GitHub](https://github.com/KhronosGroup/glTF-Tutorials/blob/main/gltfTutorial/gltfTutorial_020_Skins.md#:~:text=The%20skin%20contains%20an%20array,joint%2C%20in%20its%20initial%20configuration)). 

At runtime, when animating, you compute the current joint matrix by `worldMatrix(node) * inverseBindMatrix`. You then pass all joint matrices to the GPU for skinning (via uniform buffer or SSBO). 

Optionally, you can build a convenience `Bone` struct per joint that stores `parentIndex` and `bindPoseMatrix`, but because glTF joints are already nodes in the scene graph, you often just refer back to the `Node` transforms.

## Animations

An **Animation** holds time-sampled keyframes for nodes/joints. glTF animations consist of channels targeting node translations/rotations/scales, each with input times and output values. We convert this into per-node (or per-joint) keyframe tracks. For example:

```c
typedef enum { INTERP_LINEAR, INTERP_STEP, INTERP_CUBICSPLINE } Interpolation;

typedef struct {
    float time;
    float translation[3];
    float rotation[4];   // quaternion (x,y,z,w)
    float scale[3];
} Keyframe;

typedef struct {
    int nodeIndex;         // target node/joint index
    int keyframeCount;
    Keyframe *keyframes;   // Sorted by time
    Interpolation interp;  // glTF sampler interpolation
} AnimationChannel;

typedef struct {
    char name[64];           // Animation name (if any)
    int channelCount;
    AnimationChannel *channels;
    float startTime, endTime; // Overall animation duration
} Animation;
```

Each `AnimationChannel` corresponds to one glTF animation sampler targeting a particular node. The channel’s `keyframes` array is sorted by `time`. Interpolation modes come from glTF: `"LINEAR"` (use linear or slerp for quaternions), `"STEP"`, or `"CUBICSPLINE"` ([glTF™ 2.0 Specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#:~:text=%2A%20%60,the%20number%20of%20input%20elements)). The enum above matches these modes. 

During runtime, you advance a time value, then for each channel interpolate between the two nearest keyframes according to `interp`, and apply the resulting TRS to the node (or directly compute the joint matrix for bones). 

Citations: glTF spec defines these interpolation modes ([glTF™ 2.0 Specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#:~:text=%2A%20%60,the%20number%20of%20input%20elements)). For linear, remember to use spherical linear interpolation (SLERP) for quaternions. 

## Memory Layout & GPU Considerations

- **Packed Buffers:** Store vertex attributes in tightly packed arrays (ideally interleaved) to maximize cache coherence. glTF is designed for efficient runtime use, so after parsing you should flatten all buffer data into contiguous CPU arrays or directly into GPU buffers ([LearnOpenGL - Mesh](https://learnopengl.com/Model-Loading/Mesh#:~:text=Let%27s%20review%20a%20bit%20of,diffuse%2Fspecular%20maps)).  
- **Contiguous Upload:** Upload each Mesh’s vertex and index arrays to GPU once (e.g. with `glBufferData`). This minimizes overhead. For dynamic meshes (morph targets or skinning), you may update a separate VBO each frame.  
- **Uniform/Skinning Buffers:** Limit per-frame CPU->GPU updates. For skinning, storing all joint matrices in a uniform buffer or shader-storage buffer (instead of individual uniforms) lets you animate many bones efficiently ([Skeletal animation in glTF | lisyarus blog](https://lisyarus.github.io/blog/posts/gltf-animation.html#:~:text=Most%20skeletal%20animation%20tutorials%20suggest,can%20be%20a%20bit%20problematic)).  
- **Alignment:** Align structs in memory for GPU (e.g. 16-byte alignment for `mat4` and `vec4`). Use arrays of structs or structs of arrays as needed. For example, an array of `Vertex` is typically 32 bytes (8 floats) or more if tangent/color are included, which aligns well.  

By organizing data as above, the engine can simply reference mesh/texture indices and draw directly with GPU handles. In summary, after parsing, you have clean C structs like `Mesh`, `Material`, `Texture`, `Node`, `Skin`, and `Animation` filled with flattened data ready for rendering. Each struct’s purpose is clear, and their memory layout is optimized for GPU use (contiguous arrays, minimal indirection, and packed attributes) ([LearnOpenGL - Mesh](https://learnopengl.com/Model-Loading/Mesh#:~:text=Let%27s%20review%20a%20bit%20of,diffuse%2Fspecular%20maps)) ([How I learned Vulkan and wrote a small game engine with it](https://edw.is/learning-vulkan/#:~:text=%2F%2F%20Each%20,renderer.drawMesh%28mc.meshes%5Bi%5D%2C%20tc.worldTransform%2C%20mc.castShadow)).
